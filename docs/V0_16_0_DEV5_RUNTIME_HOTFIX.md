# v0.16.0-dev.5 运行时卡死与性能热修复

日期：2026-07-28

## 用户实机现象

- Godot 4.7.1 已能进入游戏，但建筑受到攻击时出现：
  - `take_damage: Invalid call. Nonexistent 'float' constructor.`
  - 调用位置：`scripts/game/ra2_building.gd`。
- 错误在持续交火时反复写入调试器，导致主线程明显卡顿甚至表现为卡死。
- 实测画面帧率约 24 FPS。

## 根因

### 建筑受击返回值为空

基础 `building.gd::take_damage()` 当前没有返回实际伤害值。RA2 建筑子类把 `super.take_damage()` 的空返回值保存为 `Variant`，随后执行 `float(actual)`。当 `actual == null` 时，Godot 报出不存在的 `float` 构造调用。

该错误会在每次建筑受击时重复触发，持续生成堆栈和调试器输出，本身就会严重拖慢游戏线程。

### 新增运行时规则存在无差别逐帧扫描

- `RuntimeMovementRules` 每帧遍历全部单位和建筑，即使绝大部分对象不属于坦克、矿车或待初始化建筑。
- `RuntimeTuning` 每帧遍历全部单位和建筑，并重复执行大量已经完成的一次性检查。
- 建造栏每 0.18 秒重新构建 RA2 数据字典并强制重绘所有生产卡片。
- 每次空间战斗声音都会新建并释放一个 `AudioStreamPlayer2D`，密集交火时产生频繁节点分配和回收。

## 修复

### 受击卡死

- 不再依赖基础建筑 `take_damage()` 的返回值。
- RA2 建筑在调用父类前记录 HP，调用后使用 `previous_hp - hp` 得到实际伤害。
- 删除对空返回值执行 `float(actual)` 的路径。

### 移动规则

- 单独维护坦克、矿车和普通单位列表。
- 坦克朝向稳定仅遍历坦克。
- 终点占用检查改为 0.10 秒一次。
- 矿车卸矿视觉改为 0.05 秒一次。
- 建筑血条和战车工厂视觉校正只处理尚未完成初始化的建筑。
- 距离判断优先使用平方距离，减少平方根计算。

### 运行时修正

- 单位碰撞校正改为注册后执行一次。
- 只维护矿车列表用于采矿粒子。
- 采矿粒子状态以 0.08 秒步长更新。
- 建筑损伤阶段同步以 0.12 秒步长更新。
- 建筑动画尾帧检查以 0.25 秒步长处理待检查建筑，完成后移出队列。

### 空间音频

- 增加最多 24 个 `AudioStreamPlayer2D` 的复用池。
- 战斗声音不再每次创建和销毁节点。
- 场景切换后自动清除失效播放器引用。
- 池耗尽时循环复用最早的播放器。

### 建造栏

- 缓存阵营、对象类型和对象 ID 对应的 RA2 运行时数据。
- 不再每 0.18 秒重复读取并复制完整数据字典。
- 卡片数据未变化时不再强制 `queue_redraw()`。
- 电力文本未变化时不重复写入文本。
- UI 检查间隔调整为 0.25 秒。

## 预期效果

- 建筑受击不再产生 `Nonexistent 'float' constructor`。
- 密集交火时调试器不再被同一错误持续刷屏。
- 降低每帧全对象扫描、生产卡片重绘和空间音频节点分配。

## 验证要求

当前执行环境没有 Godot 4.7.1，不能提供真实 FPS 结果。必须在用户机器验证：

1. 建筑持续受击 2 分钟，调试器不出现新的红色错误。
2. 分别记录空闲、移动大部队、密集交火三种状态的 FPS。
3. 检查坦克停止朝向、矿车卸矿和建筑修复动画没有因降频而明显跳变。
4. 检查空间声音左右声道、屏幕外静音和副官播报仍正常。
5. 检查建造栏前置条件变化后，最迟 0.25 秒内正确显示或隐藏卡片。

黄色的局部变量遮蔽提示属于代码质量警告，不是本次卡死根因，本热修复不把警告清理与性能修复混在一起。
