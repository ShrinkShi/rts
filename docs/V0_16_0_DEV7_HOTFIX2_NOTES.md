# v0.16.0-dev.7 Hotfix 2：悬崖边缘寻路与原版地形素材需求

日期：2026-07-29

## 用户实机反馈

- 坦克靠近高地悬崖边缘后会卡死，无法继续执行移动命令。
- 当前高地、坡道和悬崖仍是程序化绘制，不是《红色警戒 2 / 尤里的复仇》原版 TMP 地形素材。

## 卡住的根因

v0.16.0-dev.7 为了阻止单位直接穿越悬崖，把高地外圈的整个格子标记成了 AStar `solid`。

这会产生两个问题：

1. 高地边缘一整圈可站立区域被错误删除。
2. 单位一旦已经位于这些格子上，其 AStar 起点本身就是不可通行点，后续无法生成离开悬崖的路径，因此表现为永久卡住。

## 本次修复

### 1. 取消“整格封死悬崖”

- 启动时恢复旧版本错误标记为 solid 的悬崖边缘格。
- 恢复时保留真实的水面、岩石、建筑占用和茂密树木阻挡。
- 高地边缘格重新允许单位站立和离开。

### 2. 改为“边连接限制”

新增高度感知 A*：

- 同高度格可以正常连接。
- 不同高度格之间只有坡道方向正确时才能连接。
- 普通悬崖两侧的格子仍然可站立，但两格之间没有通行边。
- 八方向寻路禁止从悬崖拐角斜穿。
- 坡道路径增加轻微代价，但不会阻止通行。

这比把边缘格设为 solid 更接近原版 RA2 的地形拓扑。

### 3. 防止物理避让把单位推出合法路径

单位分离、`move_and_slide()` 和重叠修正可能让单位偏离 A* 路径。本次增加运行时边缘校验：

- 普通地面移动若越过非法悬崖边，会回退本帧位移。
- 随后立即重新规划经过坡道的路径。
- 冲击波将车辆真正掀起时允许越过高低差，但落地点仍不能是建筑、水面、岩石或其他不可通行格。

## 原版地形素材需求

为了停止继续使用程序化悬崖和坡道，下一阶段需要读取原版 TMP 地形、调色板和 TileSet 定义。

### 最省事的提供方式

请提供游戏目录中的：

- `ra2.mix`
- `ra2md.mix`

### 只提供地形相关内容的精简方式

也可以从上述总包中提取并提供：

- `isotemp.mix`：RA2 温带等距 TMP 地形，包含地表、坡道、悬崖等主体资源。
- `isotemmd.mix`：尤里的复仇温带新增/覆盖地形。
- `isotem.pal`：温带等距地形调色板。
- `temperat.ini`：RA2 温带 TileSet 编号与文件映射。
- `temperatmd.ini`：YR 对温带 TileSet 的扩展和覆盖。

当前优先只做温带地图，因此暂时不需要 `isosnow.mix`、`isourb.mix` 等其他剧院包。后续扩展雪地、城市、新城市、沙漠和月球时再补对应 MIX 与 PAL。

## 仍需实机验证

1. 原先卡住的坦克是否能立即离开悬崖边缘。
2. 从高地内部点击低地时，单位是否自动绕到最近坡道。
3. 从低地点击高地时，单位是否自动寻找坡道。
4. 单位是否还能从非坡道位置直接跨越悬崖。
5. 多辆坦克在坡道入口拥挤时是否会重新出现摇摆或卡死。
6. 冲击波掀起的车辆是否仍能飞越悬崖并正常落地。
7. Godot 4.7.1 是否出现新的 Parser Error 或性能下降。
